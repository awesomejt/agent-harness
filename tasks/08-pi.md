# Phase 8 — Pi portability

Status checkboxes live only in [PROJECT.md](../PROJECT.md). These cards specify dependencies and evidence; their order is the recommended work order, not a second status board. See [task conventions](README.md).

<a id="p8-1"></a>
## P8.1 — Pi integration and mapping decisions

- **Depends on:** [P4.6](04-core-mvp.md#p4-6)
- **Deliverable and boundary:** Choose Pi interface, authentication/model routing, canonical-agent/skill representation and enforceable permission mapping from supported APIs.
- **Acceptance evidence:** Decision/capability record identifies non-equivalent features and a testable control/terminal protocol without adopting advisory restrictions as enforcement.
- **Decision/readiness gate:** May follow core MVP independently of sequences/Ralph; no assumption of exact OpenCode parity.
- **Contract:** [docs/FRAMEWORKS.md](../docs/FRAMEWORKS.md); status/evidence summary in [PROJECT.md](../PROJECT.md).

<a id="p8-2"></a>
## P8.2 — Pi single-run adapter

- **Depends on:** [P8.1](08-pi.md#p8-1)
- **Deliverable and boundary:** Implement primary/specialized execution behind existing policy and normalized outcomes. Preserve lifecycle, routing and supported constraints.
- **Acceptance evidence:** Fixtures and controlled lifecycle tests cover route restrictions, protocol completion, cancellation and capability refusal.
- **Decision/readiness gate:** Do not copy runtime default auth/model behavior without effective-route validation.
- **Contract:** [docs/EXECUTION.md](../docs/EXECUTION.md); status/evidence summary in [PROJECT.md](../PROJECT.md).

<a id="p8-3"></a>
## P8.3 — Pi single-run acceptance

- **Depends on:** [P8.2](08-pi.md#p8-2)
- **Deliverable and boundary:** Demonstrate Pi primary/specialized project tasks and supported single-run parity. Document permission/model/context differences and install/version requirements.
- **Acceptance evidence:** Live task evidence and capability docs close the initial Pi adapter milestone; sequence/Ralph parity is explicitly pending P8.4, not claimed by this task.
- **Decision/readiness gate:** Can complete before Phase 6; do not mark full workflow parity supported until P8.4 passes.
- **Contract:** [docs/IMPLEMENTATION.md](../docs/IMPLEMENTATION.md); status/evidence summary in [PROJECT.md](../PROJECT.md).

<a id="p8-4"></a>
## P8.4 — Pi sequence and Ralph parity follow-up

- **Depends on:** [P8.3](08-pi.md#p8-3), [P6.4](06-ralph.md#p6-4)
- **Deliverable and boundary:** Run the implemented sequence/Ralph workflows through Pi using common route/agent/state rules, covering permitted context and verification semantics.
- **Acceptance evidence:** Workflow fixture/live evidence demonstrates supported parity and recovery; unsupported portions are explicitly refused/documented. Close Phase 8 only after this follow-up.
- **Decision/readiness gate:** This extracts later workflow parity from P8.3 so early Pi use is not blocked on unimplemented workflows.
- **Contract:** [docs/WORKFLOWS.md](../docs/WORKFLOWS.md); status/evidence summary in [PROJECT.md](../PROJECT.md).
