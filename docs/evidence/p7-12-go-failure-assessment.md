# P7.12 stopped Go attempt: offline assessment

This source-only assessment follows the [stopped attempt](p7-12-go-live-setup.md#bounded-live-observation--stopped). No authentication, provider request, model turn, retained credential inspection or retry was performed.

In `src/acp.rs` at commit `37fe239`, the prompt request's error propagates out of the foreground task; the outer connection result is reduced to `value.is_ok()`. Once a prompt is active, unsuccessful connection completion without a protocol violation produces the same `runtime/provider/transport failure or cancellation response timeout` message. The result therefore does not retain an ACP error code, message or data that could identify the source. Zero stderr bytes and zero observed tool events do not recover that lost error or establish that the provider did not receive the request. The 0.2-second interval between submission and failure is an observation, not a diagnosis. The disposable project and runtime state were removed, so this record cannot be supplemented from their logs.

OpenCode's [2.4.0 release notes](https://github.com/anomalyco/opencode/releases/tag/v2.4.0) mention a Go connection-dialog change and asynchronous plugin loading, but neither shows that either caused this failure. The isolated installed-runtime Go probe establishes session/model setup with a synthetic key and intercepted prompt, not authenticated inference. The user said the key should be correct; its workspace association was not independently verified. Authentication, entitlement, provider error, protocol or transport failure remain possibilities, not findings.

A future separately reviewed diagnostic design can evaluate retaining a bounded, allowlisted ACP error classification without raw provider messages, tokens or untrusted data. It needs adversarial redaction fixtures, explicit unknown handling and the existing uncertain-effect/no-replay policy. Raw error text, account state or another request must not be collected merely to fill the gap. Any live continuation needs its own reviewed scope and fresh account attestation; no specific retry, different model or weakened gate is selected here. P7.12 remains open.
