# OpenCode 2.4 compatibility

D106 proposes qualifying stable 2.4.x alongside 2.3.x on merge; installed 2.4.1 on macOS arm64 is the tested 2.4 version. The tested Homebrew executable SHA-256 is `16a54b561fdad1a19be209ddc23990844a2368dad4864c18ca109372a46bb26a`. This is a runtime compatibility increment, not P7.12 live acceptance.

The [2.4.0 release notes](https://github.com/anomalyco/opencode/releases/tag/v2.4.0) introduce automations (including scheduled shell actions), restored `CLAUDE.md` discovery, background plugin loading, image/video tools, a Go connection UI change and ACP session cleanup. The [2.4.1 notes](https://github.com/anomalyco/opencode/releases/tag/v2.4.1) include a config-only provider display fix. Release notes alone do not prove isolation or Go account entitlement.

The harness explicitly sets `OPENCODE_DISABLE_CLAUDE_CODE` in its private environment. A local deterministic model stub checks root, parent and nested instructions, denied resources, constrained reviewer, tool inventory, refusal of a direct automation tool call and slash-command prompts including `/automation`. The trusted coding and cancellation probes use the real installed runtime and local stub, with independent project checks. The native-runtime shim intercepts prompts before provider submission: both Zen and Go exercise real preflight and ACP session setup, and Go uses synthetic credentials for cloud-only deny/trusted and unreachable-proxy fallback. These checks do not contact a model provider or verify live Go usage. Existing no-plugin, source, catalog, helper and policy checks continue to fail closed; background loading remains a reason to preserve those checks rather than a claim about arbitrary plugins.

No Go model turn, account setting check, natural limit test or paid allowance verification was performed. P7.12 still requires separately reviewed live coding and constrained-review acceptance with a fresh operator attestation. P7.9's separately pinned experiments remain unchanged.

Validation: `cargo test --locked`, locked Clippy with warnings denied, formatting and documentation-link checks passed. The 53-suite offline run passed 52 suites; the mode matrix initially failed because its exact environment allowlist omitted the new switch. After updating that fixture, the mode matrix passed separately (166 cases). The strengthened Go fallback model assertion also passed in a separate rerun. No full-suite rerun is claimed after those fixture-only changes.
