# P7.12 — Go live acceptance setup

This is a proposed setup for review, not live acceptance. The operator selected `opencode-go/beam-free` on 2026-11-25; this free model cannot establish paid Go entitlement, paid allowance consumption, or natural limit behavior. The 2.4.1 runtime qualification is [D106](../../DECISIONS.md#2026-11-25--d106-qualify-opencode-24x) and [PR #135](https://github.com/awesomejt/agent-harness/pull/135). The account and Extra Usage state are not programmatically verified.

`scripts/tests/go_live.py` is an opt-in adaptation of the P7.2 driver. It requires the exact Homebrew OpenCode 2.4.1 executable and `AH_P712_LIVE=operator-attested` plus the non-synthetic `P712_KEY`; it removes these two environment variables before other child processes and supplies the key only to the harness. The project config contains the key name, not its value. Build with the key absent, fingerprint the binary and runtime, and obtain setup review and a fresh same-session operator attestation of the Go subscription workspace, active plan, and Extra Usage off before supplying the key. The gate variable is not persisted. Do not deliberately exhaust allowance.

One driver execution makes at most four provider turns in a disposable Git project, stopping at the first failed assertion with no retry. It uses a broken arithmetic function, independent tests, sample reviewer/coder roles, a dirty tracked sentinel, a project instruction marker and an outside file. The reviewer is asked to read the outside file and write findings; it must identify the subtraction defect with no grants or project changes, and the outside sentinel must not appear in its response. These observations do not directly prove whether an outside read was attempted or denied; the existing permission fixtures cover that boundary. The coder is asked to repair the function and run tests; only the source may change (apart from Python cache) and an independent test must pass. Each role runs cloud-only and then via local-first fallback from a bound non-listening loopback endpoint. JSON records must identify exact Go model, role, route, submitted prompt, `end_turn` and confirmed cleanup; fallback must identify an unlaunched, unsubmitted primary. The script prints sanitized counters and bounded harness diagnostics rather than responses or credentials. It makes no claim of operating-system sandboxing. Any failure, interruption, uncertain effect, unexpected output or cleanup issue is a stop for review, not permission to retry. Existing fixture evidence covers limit refusal and cancellation; this live setup does not force either.

Before setup review no inference is authorized. Offline checks: Python compilation and the optimized-Python refusal passed; missing gate, synthetic key and missing expected runtime each refused before project setup and provider contact. The production binary was built without `P712_KEY`; it must be rebuilt and fingerprinted from the reviewed revision before live execution. This setup alone does not complete P7.12.
