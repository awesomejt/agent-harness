The gate variable is not persisted. Do not deliberately exhaust allowance.

The reviewer is asked to read the outside file and write findings; it must identify the subtraction defect with no grants or project changes, and the outside sentinel must not appear in its response. These observations do not directly prove whether an outside read was attempted or denied; the existing permission fixtures cover that boundary. The coder is asked to repair the function and run tests; only the source may change (apart from Python cache) and an independent test must pass. Each role runs cloud-only and then via local-first fallback from a bound non-listening loopback endpoint. JSON records must identify exact Go model, role, route, submitted prompt, `end_turn` and confirmed cleanup; fallback must identify an unlaunched, unsubmitted primary. The script prints sanitized counters and bounded harness diagnostics rather than responses or credentials. It makes no claim of operating-system sandboxing. Any failure, interruption, uncertain effect, unexpected output or cleanup issue is a stop for review, not permission to retry. Existing fixture evidence covers limit refusal and cancellation; this live setup does not force either.

Before setup review no inference is authorized. Offline checks: Python compilation and the optimized-Python refusal passed; missing gate, synthetic key and missing expected runtime each refused before project setup and provider contact.
