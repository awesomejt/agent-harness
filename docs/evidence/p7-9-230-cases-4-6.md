## Selection

**Rerun the whole D094 matrix minus case 3 (cases 1, 2, 4, 5, 6) in one
attempt.** Do not run cases 4–6 alone.

- D094's qualification is one installed run on one host state, with
  transport/containment controls first. Splicing new cases 4–6 onto the
  2026-11-15 cases 1–2 would mix two runs, so the qualification would not come
  from a single observation. Rerunning cases 1–2 costs two fresh disposable
  roots and nothing else.
- The rows, their order and their D094 labels are unchanged. Case 6 stays the
  only ancestor-undenied positive control. After D101, no row denies listing on
  a watched directory.

**Reuse the merged D094 helper unchanged.** The wrapper
`chatgpt_230_observer_matrix.py` imports `chatgpt_230_observer` and calls its
`audit`, executable pin, `transport_controls` and `run_case` directly. It
replaces only `main`'s row loop. The source audit and the hash
`95af97f3…2db7` still pin both the source and the executable. The
transport/containment controls, which include D094's synthetic
listing/fallback pair, still run before any case. Every per-case gate is
inherited: fixed 236-ID inventory, zero connections, exact built-in plugins,
documents, agent canaries, deny tails, settling and the WARN/ERROR,
watcher, spawn and MCP log gates.

**Do not add the D100 Bun cache control.** D100 was needed only because D099's
primitive gate refuses any created state. D094 has no such gate. Its roots are
private and temporary, so a Bun cache write under the private `XDG_CACHE_HOME`
is deleted with the root. Cases 1–2 passed in this exact environment, and
changing it would make this rerun's evidence differ from theirs. If a
cache-related observation now refuses, that is a stop for a separately reviewed
decision, not something this wrapper absorbs.

Rejected:
- a `--cases` flag on the merged D094 helper, which would change a reviewed
  artifact for a one-row removal;
- running cases 4–6 alone, which splices two runs;
- adding warning exceptions or widening fixtures.
