**Rust design and dependencies.** The modular monolith remains proportionate: `config` resolves requests; `verify` owns check validation/execution; `sequence` coordinates snapshots, steps and resume; `state` owns records and locks; `single` owns the shared launch/fallback service; `process` owns group cleanup; and `progress` owns human/machine output. OpenCode still owns the inner coding loop. No speculative backend traits or database were added. `sequence.rs` combines several responsibilities and is a future extraction candidate, but file length alone is not a defect. Generic SHA-256 functionality currently lives in `state` and is also used by `agents`; a shared utility can be considered if further consumers justify it.

The new dependency is pinned `sha2 = 0.10.9` with default features disabled. [P5.2 evidence](../evidence/p5-2-ordered-execution.md#dependency) records its transitive versions, license evaluation, Rust 1.88 compatibility and a packaging check. The notice collector's reviewed license map covers those expressions. Locked debug/release builds were repeated here; fresh packaging, installation and release publication were not.

**State and threat boundaries.** The records retain identities/outcomes rather than prompts, responses, check output, argv text or credentials. Advisory locking does not contain another host process; a concurrent `ah single`, detached processes, SIGKILL cleanup and exactly-once effects remain explicitly outside the guarantee. Configured checks run current project content with host privileges, and are not a sandbox. These limits do not excuse K05-01, which violates the narrower, explicit program-path trust check.

### K05-01 reproduction

Use a disposable project and directories outside it:

```text
outside/safe/checker                    # executable, exits 1
project/replacement/checker             # executable, creates a marker, exits 0
project/check-dir -> outside/safe
outside/tools/alias -> project/check-dir
checks.test.argv = ["/absolute/outside/tools/alias/checker"]
```

1. Run `ah single Task --project PROJECT --verify test --permissions trusted --preview` with valid fixture config/key references. Observed exit 0 and `pinned outside the project`.
2. In a disposable copy of `scripts/tests/fake_opencode.py`, add a prompt-handler action that unlinks `project/check-dir` and recreates it pointing to `project/replacement`; otherwise use its existing successful `text` case.
3. Run the same invocation without `--preview`. Observed exit 0, verification `passed`, and the replacement program's marker in the project. The intended external check would have returned 1.

`outside()` sees the canonical parent `outside/safe` and returns success without examining the intermediate project directory symlink. It later executes the original alias path, which follows the changed symlink. This is a localized trust/verification correctness defect, not evidence of a general sandbox escape: trusted execution already has host privileges. Regression tests should reject this configuration before runtime launch, cover in-project directory symlinks and mixed external/project chains, and retain passing external alias/rustup-style dispatch cases.
